</li><li><code>squeeze()</code>：删除<strong>所有长度为 1</strong> 的维度（降维）</li></ul> <br><blockquote> <br> <p><strong>先搞懂什么叫"维度的长度"</strong></p> <br> <p>形状 (2, 3) 读作"第 0 维长度 2、第 1 维长度 3"</p> <br> <p>长度 = 沿着这个维度数数，能数出几个元素。</p> <br> <p>落到打印上就一条规则：<strong>一层方括号 = 一个维度，括号里装了几个东西 = 这一维的长度</strong>。</p> <br></blockquote> <br><p>用「数括号」的方式理解维度，对照表如下：</p> <br><table><thead><tr><th>写法</th><th>括号层数</th><th>维度</th><th>形状</th></tr></thead><tbody><tr><td><code>[1, 2, 3, 4, 5]</code></td><td>1 层</td><td>1 维</td><td><code>(5,)</code></td></tr><tr><td><code>[[1, 2, 3, 4, 5]]</code></td><td>2 层</td><td>2 维</td><td><code>(1, 5)</code></td></tr><tr><td><code>[[1], [2], [3], [4], [5]]</code></td><td>2 1 层括号 → 1 维，装 5 个数 → (5,)<br>[[1, 2, 3, 4, 5]]          # 2 层括号 → 2 维，外层装 1 行 → (1, 5)<br>[[1], [2], [3], [4], [5]]  # 2 层括号 → 2 维，外层装 5 行，每行装 1 个数 → (5, 1)</code></pre> <br><p>所以"长度为 1 的维度"就是那层括号里只装了一个东西。unsqueeze 加一层"只装一个东西"的括号，squeeze 把这种括号拆掉——数据一个不动，变的只是"层级"。</p> <br><p><code>unsqueeze</code> 插长度 1 维度:</p> <br><div> <br> <p class="img-center"><img alt="" height="372" src="https://i-blog.csdnimg.cn/direct/859bf43291e34c31b4bd1179474e0ddc.png" width="600" /></p> <br></div> <br><h4 id="" name=""></h4> <br><p>虚线面是二维输入；其后方的实心框是三维结果。注意：<strong>图像不能改变</strong>——一个尺寸为 1 的轴不占用空间，它<strong>仅在插入位置处存在</strong>。换句话说，unsqueeze 只是给张量"加了一层空壳"（长度为 1 的维度），数据本身一个都没动，只是维度层级变高了。</p> <br><p><code>squeeze</code> 删除长度 1 维度:</p> <br><p class="img-center"><img alt="" height="376" src="https://i-blog.csdnimg.cn/direct/86e86b68c30e47adb1caa0acd71112de.png" width="600" /></p> <br><p></p> <br><p></p> <br><p>长度为 1 的维度不占用任何数据空间，因此 unsqueeze / squeeze 只改变张量的<strong>维度数（RANK）</strong>——比如从一维变二维，而元素总数、元素值、内存数据全部不变。配图中：有颜色的部分是真实数据，透明的"幽灵框"只是示意长度为 1 的维度，画出来好看，不占地方。</p> <br><p></p> <br><blockquote> <br> <ul><li><strong>RANK（秩）= 维度数 = shape 里数字的个数</strong>。(5,) 秩为 1；(1,5) 秩为 2；(2,3,4) 秩为 3。</li><li><strong>尺寸(size) = 某一维的长度</strong>。"尺寸为 1 的轴"就是我们上面说的"长度为 1 的维度"。</li><li><strong>为什么"不占用空间"</strong>：元素总数 = 各维长度相乘，乘 1 永远不变。所以 (5,) → (1,5) <br><div> <br> <pre><code class="language-python">t = torch.tensor([1, 2, 3, 4, 5])         # 一维: (5,)<br>t2 = t.unsqueeze(0)     # 在 0 号位置前插入长度 1<br>print(t2, t2.shape)<br>tensor([[1, 2, 3, 4, 5]]) <br><blockquote> <br> <p><strong>几个疑问的答案</strong>：</p> <br> <p><strong>为什么打印多了一层 <code>[]</code></strong>：长度为 1 的新维度在打印时表现为"多包一层方括号"。<code>unsqueeze(0)</code> 把整行包起来（1×5），<code>unsqueeze(1)</code> 的一维张量，dim ∈ [-2, 1]；对 (2, 3) 的二维张量，dim ∈ [-3, 2]。超出范围报错——代码里三维上就不可以了：对二维张量 <code>unsqueeze(3)</code> 越界。</p> <br></blockquote> <br><h4 id="" name=""></h4> <br><pre><code class="language-python"># 对 2 行 3 列张量升维<br>t1 = torch.randint(1, 10, (2, 3))<br>print(t1.unsqueeze(0).shape)   # torch.Size([1, 2, 3])  整表包一层<br>print(t1.unsqueeze(1).shape)   # torch.Size([2, 1, 3]) 这种就是真重排），非连续张量上还可能复制数据；</li><li>其实 <code>reshape(1, 5)</code> 也能达到和 <code>unsqueeze(0)</code> 一样的效果——区别只在"用途专用"与"通用"。</li></ul> <br><p></p> <br><h4 id="1.4%20transpose()%20%2F%20permute()%EF%BC%9A%E4%BA%A4%E6%8D%A2%E7%BB%B4%E5%BA%A6" name="1.4%20transpose()%20%2F%20permute()%EF%BC%9A%E4%BA%A4%E6%8D%A2%E7%BB%B4%E5%BA%A6">1.4 transpose() / permute()：交换维度</h4> <br><ul><li><code>transpose(dim0, dim1)</code>：一次交换<strong>指定的两个维度</strong></li><li><code>permute(dims)</code>：一次<strong>重排所有维度</strong>（把每个维度的新顺序列出来）</li></ul> <br><p class="img-center"><img alt="" height="372" src="https://i-blog.csdnimg.cn/direct/7420a2c6a6654e7b8453a6e21c1546eb.png" width="600" /></p> <br><blockquote> <br> <p>原话:每一行变为一列:虚线为4宽3高，实线为3宽4高。轴交换步长且无数据复制，因此x.T不再连续。</p> <br></blockquote> <br><p>transpose 的直观效果：原来的行变成列，即"转置"。</p> <br><p>输入形状 (4,3)（淡色块）→ 输出形状 (3,4)（实色块），两块叠加在同一原点。</p> <br><p>底层机制：不搬数据，只把两个轴的 <strong>stride（步长）</strong> 互换。<strong>stride 是"沿某维走一步要跳几个内存位置"，换一下步长就等于换了解读方式。</strong></p> <br><p>因为只改步长、不搬数据，所以 transpose 返回的是 <strong>view</strong>（共享内存）。步长换了之后，"显示顺序"和"内存顺序"对不上 → <code>is_contiguous()</code> 变 False → 这正是文章 1.5 里 <code>view()</code> 会报错、要先 <code>contiguous()</code> 的根因。</p> <br><p></p> <br><p class="img-center"><img alt="" height="386" src="https://i-blog.csdnimg.cn/direct/0301fee7a60a4eb399298e265a53585e.png" width="600" /></p> <br><p></p> <br><div></div> <br><blockquote> <br> <p>原话:轴被重新标记，但未移动:颜色仍追踪原始的dim-1索引。没有数据复制——只有步长顺序改变。(虚线块=输入，实线块=输出，一个原点)。</p> <br></blockquote> <br><p>permute 不搬数据元素，只给每个轴<strong>重新贴标签</strong>（原来叫第 0 维，现在叫第 1 维，等等）。图里用颜色标记"原始的第 1 维"，转完之后数据没动，动的只是"哪条轴叫什么"。</p> <br><p>和 transpose 同理：只改 stride 的<strong>顺序</strong>（transpose 是换两个，permute 是重排全部），不复制数据，返回 view。</p> <br><p>画法约定：两块叠在同一原点，看形变</p> <br><pre><code class="language-python">data = torch.arange(1, 61).reshape(3, 4, 5)   # 3×4×5 的确定性数据, 共 60 个<br># 1. 交换 1 和 2 维: (3, 4, 5) -> (3, 5, 4)<br>print(torch.transpose(data, 1, 2).shape)      # torch.Size([3, 5, 4])<br>2. 想变到 (4, 5, 3)? transpose 要连做两次<br>d2 = torch.transpose(data, 0, 1)    # (4, 3, 5)<br>d3 = torch.transpose(d2, 1, 2)      # (4, 5, 3)<br>print(d3.shape)                     # torch.Size([4, 5, 3])<br>3. permute 一步到位: 把"第 1 维放最前, 第 2 维放中间, 第 0 维放最后"<br>print(torch.permute(data, [1, 2, 0]).shape)   # torch.Size([4, 5, 3])<br>print(data.permute([1, 2, 0]).shape)          # 同上, 方法写法</code></pre> <br><p>permute 的参数含义：<code>[1, 2, 0]</code> 表示"新张量的第 0 维 = 原来的第 1 维，第 1 维 = 原来的第 2 维，第 2 维 = 原来的第 0 维"。新 shape 的每一维长度 = 原 shape 对应位置的长度：原 (3,4,5) → 新 (4,5,3)。</p> <br><blockquote> <br> <p><strong>总结</strong>:transpose 和 permute 本质都是<strong>只改步长、不搬数据</strong>——所以快、省内存，但代价是结果<strong>不连续</strong>(后面要 <code>view()</code> 就得先 <code>contiguous()</code> 把数据按新顺序重写一遍)。<strong>形状变了、数据没动</strong>。</p> <br></blockquote> <br><h4 id="" name=""></h4> <br><h4 id="1.5%20view()%20%E4%B8%8E%20contiguous()%EF%BC%9A%E5%86%85%E5%AD%98%E8%BF%9E%E7%BB%AD%E6%80%A7" name="1.5%20view()%20%E4%B8%8E%20contiguous()%EF%BC%9A%E5%86%85%E5%AD%98%E8%BF%9E%E7%BB%AD%E6%80%A7">1.5 view() 与 contiguous()：内存连续性</h4> <br><p><strong>第 1 步 · 先建立一个概念：内存是一条线</strong></p> <br><p>张量无论几维，内存里其实都是"一条线"排开的。以 <code>data = torch.tensor([[10, 20, 30], [40, 50, 60]])</code> 为例，6 个元素在内存里的真实存储顺序永远是：</p> <br><pre><code class="language-python">内存:   10  20  30  40  50  60<br></code></pre> <br><p><strong>第 2 步 · view 的思路：不搬数据，只换"切法"</strong></p> <br><p></p> <br><p class="img-center"><img alt="" height="383" src="https://i-blog.csdnimg.cn/direct/900cf1e99fe640baadf48752d46d3981.png" width="600" /></p> <br><p>view 和 reshape 一样能改形状，但view并不复制数据，而是在原内存上换一种"切法"来读：每行切几个数一变，形状就变了。</p> <br><pre><code class="language-python">(2,3) 的切法:     [10 20 30] [40 50 60]   → 2 行 3 列<br>view(3,2) 的切法: [10 20] [30 40] [50 60] → 3 行 2 列<br></code></pre> <br><p>同一块内存、同一批数，只是"切法"变了。因为从头到尾没复制过数据，所以 view 快、省内存。</p> <br><p><strong>第 3 步 · view 的硬要求：内存必须连续</strong></p> <br><ul><li><strong>连续</strong> = "张量显示出来的顺序"和"内存里实际存的顺序"一致。</li><li>新创建的张量默认连续（<code>is_contiguous()</code> → True），所以新建后直接 view 没问题。</li></ul> <br><p><strong>第 4 步 · 问题出在 transpose / permute 之后</strong></p> <br><p>这两个操作只改步长、不搬数据：显示顺序变了，内存里数据还按老顺序躺着，两者对不上，就变成"不连续"。看 <code>t3 = torch.transpose(data, 0, 1)</code>：</p> <br><pre><code class="language-python">t3 显示:  10  40       按显示顺序读, 需要的内存是: 10 40 20 50 30 60<br>          20  50       内存里实际存的却是:        10 20 30 40 50 60  ← 对不上!<br>          30  60<br></code></pre> <br><p><strong>为什么这时 view 会直接报错</strong>：view 的承诺是"绝不搬数据"。面对一块按老顺序躺着的内存，它没法既不搬数据、又按 t3 显示的样子切出 (2,3)——做不到，就宁可报错，也不偷偷复制。</p> <br><p><strong>第 5 步 · contiguous() 可以解决不连续</strong></p> <br><p></p> <br><p class="img-center"><img alt="" height="375" src="https://i-blog.csdnimg.cn/direct/c7b6f42ad1174edaa911acdcacee8818.png" width="600" /></p> <br><p>它把数据按当前显示的顺序重新写一遍内存（复制一份）：10, 40, 20, 50, 30, 60。写完之后，显示顺序和内存顺序重新对上，变回连续，view 就能用了。</p> <br><p><strong>标准写法</strong>：</p> <br><pre><code class="language-python">t3 = torch.transpose(data, 0, 1)   # 不连续了<br>t4 = t3.contiguous().view(2, 3)    # 先重写内存变连续, 再 view<br></code></pre> <br><p>完整过程验证：</p> <br><pre><code class="language-python">data = torch.tensor([[10, 20, 30], [40, 50, 60]])<br>1. 新张量: 连续<br>print(data.is_contiguous())            # True<br>2. view 直接变形: (2,3) -> (3,2)<br>t2 = data.view(3, 2)<br>print(t2)<br>tensor([[10, 20],<br>[30, 40],<br>[50, 60]])<br>print(t2.is_contiguous())              # True<br>3. transpose 之后: 不连续了<br>t3 = torch.transpose(data, 0, 1)<br>print(t3)<br>tensor([[10, 40],<br>[20, 50],<br>[30, 60]])<br>print(t3.is_contiguous())              # False<br>t3.view(2, 3)   # 报错! view 不能用于非连续张量<br>4. 先 contiguous 变连续, 再 view<br>print(t3.contiguous().is_contiguous()) # True<br>t4 = t3.contiguous().view(2, 3)<br>print(t4)<br>tensor([[10, 40, 20],<br>[50, 30, 60]])</code></pre> <br><p><strong>注意：contiguous().view() 不是"还原"</strong></p> <br><p>t4 是 <code>[[10,40,20],[50,30,60]]</code>，而不是原来的 <code>[[10,20,30],[40,50,60]]</code>：</p> <br><pre><code class="language-python">contiguous() 后的内存: 10  40  20  50  30  60    (按 t3 显示的样子重铺)<br>view(2,3) 的切法:      [10 40 20] [50 30 60]    → [[10,40,20],[50,30,60]]<br></code></pre> <br><p>因为 contiguous() 是<strong>按 t3 当前显示的样子</strong>重新铺内存，view 只是在这份新内存上重新切形状——它俩都不知道"原来长什么样"，所以结果回不去了。</p> <br><p><strong>总结</strong>：view 是"不搬数据只换切法"，要求内存连续；transpose / permute 只改步长不搬数据，会破坏连续性；contiguous 专门把不连续的张量按显示顺序重写一遍内存，让 view 重新可用。reshape 则更"圆滑"——能 view 就 view，不能就自动复制一份再切，所以 reshape 永远不报错，而 view 会。</p> <br><p></p> <br><h4 id="1.6%20%E5%B0%8F%E7%BB%93" name="1.6%20%E5%B0%8F%E7%BB%93">1.6 小结</h4> 2，只是被拼的那一维变长了。要求是：除拼接维外，其他维度必须一致,否则拼不上。</p> <br><div> <br> <pre><code class="language-python">data1 = torch.tensor([[[7, 8, 7], [6, 3, 6]]])      # (1, 2, 3)<br>data2 = torch.tensor([[[3, 6, 5], [7, 2)</code></pre> <br></div> <br><p><strong>dim 是"沿着哪条边接"</strong>：拼 0 维 = 摞表、拼 1 维 = 接行、拼 2 维 = 接列。被拼接的那个维度长度变成两者之和，其余维度不变。</p> <br><h4 torch.stack()：开辟新维度堆叠</h4> <br><p>把多个形状完全相同的张量摞起来，会多出一个新维度。在新维度上堆叠，会增加一个新维度，所以stack函数会开一个新维度，维度数 +1。</p> <br><p class="img-center"><img alt="" height="377" src="https://i-blog.csdnimg.cn/direct/c55a83e427a54ce08113c0b665ff57fc.png" width="600" /></p> <br><p>比如两个 (2,3) 的张量，stack(dim=0) 变成 (2,2,3)——多出来的那个 2 就是"两个张量"这个维度。要求是：所有输入张量形状必须完全相同。</p> <br><div> <br> <pre><code class="language-python">data1 = torch.tensor([[6, 2, 8], [9, 8, 3]])    # (2, 3)<br>data2 = torch.tensor([[9, 2, 8], [0, 7, 9]])    # (2, 3)<br>dim=0: 两张表摞起来 -> (2, 2, 3)<br>print(torch.stack([data1, data2], dim=0).shape)   # torch.Size([2, 2, 3])<br>dim=1: 按"行"为单位交错 -> (2, 2, 3)<br>结果: [[data1第0行, data2第0行], [data1第1行, data2第1行]]<br>print(torch.stack([data1, data2], dim=1).shape)   # torch.Size([2, 2, 3])<br>dim=2: 按"元素"为单位配对 -> (2, 3, 2)<br>结果: data1[i][j] 和 data2[i][j] 配成一队<br>print(torch.stack([data1, data2], dim=2).shape)   # torch.Size([2, 3, 2])</code></pre> <br></div> <br><p>stack 的 dim 指的是"<strong>新维度插在哪个位置</strong>"：dim=0 按整张表摞、dim=1 按行配对、dim=2 按元素配对。</p> <br><h4 id="2.3%20cat%20%E4%B8%8E%20stack%20%E5%AF%B9%E6%AF%94" <br><table><thead><tr><th>函数</th><th>维度数</th><th>要求</th><th>一句话</th></tr></thead><tbody><tr><td><code>torch.cat()</code></td><td>不变</td><td>除拼接维外其余维度一致</td><td>"接长"某个已有维度</td></tr><tr><td><code>torch.stack()</code></td><td>+1</td><td>输入形状完全相同</td><td>"开一个新维度"把张量摞进去</td></tr></tbody></table> <br><div> <br> <pre><code class="language-python"># 2 维张量:<br>t1 = torch.randint(1, 10, (2, 3))<br>t2 = torch.randint(1, 10, (2, 3))<br>print(torch.cat([t1, t2], dim=0).shape)    # torch.Size([4, 3])<br>print(torch.cat([t1, t2], dim=1).shape)    # torch.Size([2, 6])<br># torch.cat([t1, t2], dim=2)   # 报错! 2 维张量的 dim 合法范围是 [-2, 1], 没有 2 维<br>print(torch.stack([t1, t2], dim=0).shape)  # style="background-color:transparent">三、自动微分模块</h3> <br><h4 id="" name=""></h4> <br><h4 id="3.1%20%E5%85%88%E5%9B%9E%E7%AD%94%EF%BC%9A%E5%89%8D%E9%9D%A2%E5%AD%A6%E9%82%A3%E4%B9%88%E5%A4%9A%E5%87%BD%E6%95%B0%EF%BC%8C%E5%88%B0%E5%BA%95%E4%B8%BA%E4%BA%86%E4%BB%80%E4%B9%88" name="3.1%20%E5%85%88%E5%9B%9E%E7%AD%94%EF%BC%9A%E5%89%8D%E9%9D%A2%E5%AD%A6%E9%82%A3%E4%B9%88%E5%A4%9A%E5%87%BD%E6%95%B0%EF%BC%8C%E5%88%B0%E5%BA%95%E4%B8%BA%E4%BA%86%E4%BB%80%E4%B9%88">3.1 先回答：前面学那么多函数，到底为了什么</h4> <br><blockquote> <br> <p>从《01》到现在，我们学了张量创建、数值计算、运算函数、索引、形状操作、拼接——它们都是"积木"。积木本身不是目的，搭出一个能"学习"的模型才是目的。</p> <br></blockquote> <br><p>什么叫"学习"？以预测问题为例：</p> <br><ul><li>我们假设规律长成 <code>z = wx + b</code> 这样一条直线：z 是预测值，x 是输入特征，w（权重）和 b（偏置）是两个可以拧的"旋钮"，术语叫<strong>参数（Parameters）</strong>。</li><li>所谓"学习"，就是把 w、b 这两个旋钮拧到合适的值，让预测值 z 贴近真实值 y。</li><li>旋钮一开始是随便拧的（随机初始化），预测必然离谱。</li></ul> <br><blockquote> <br> <p>术语讲解：只有一个特征 x 时叫<strong>一元线性模型</strong>；"多元线性"指它的推广形式 <code>y = w₁x₁ + w₂x₂ + … + b</code>——每个特征各配一个旋钮（权重），原理完全相同。本章统一用最简形式演示。</p> <br></blockquote> <br><p>于是"学习"这件事，顺理成章拆成四个环环相扣的问题，也是本章前半段的路线：</p> <br><table><thead><tr><th>顺序</th><th>问题</th><th>由谁回答</th></tr></thead><tbody><tr><td>①</td><td>怎么知道当前旋钮拧得效果？</td><td>损失函数（3.2）</td></tr><tr><td>②</td><td>旋钮该往哪个方向拧？</td><td>梯度（3.3）</td></tr><tr><td>③</td><td>方向有了，具体怎么拧？</td><td>梯度下降（3.4）</td></tr><tr><td>④</td><td>模型有百万个旋钮时，方向算不过来怎么办？</td><td>自动微分（3.5 起）</td></tr></tbody></table> <br><h4 id="3.2%20%E7%AC%AC%E4%B8%80%E6%AD%A5%EF%BC%9A%E7%AE%97%E4%B8%80%E7%AE%97%E5%BD%93%E5%89%8D%E5%B7%AE%E8%B7%9D%E5%A4%9A%E5%A4%A7%E2%80%94%E2%80%94%E6%AD%A3%E5%90%91%E4%BC%A0%E6%92%AD%E4%B8%8E%E6%8D%9F%E5%A4%B1" name="3.2%20%E7%AC%AC%E4%B8%80%E6%AD%A5%EF%BC%9A%E7%AE%97%E4%B8%80%E7%AE%97%E5%BD%93%E5%89%8D%E5%B7%AE%E8%B7%9D%E5%A4%9A%E5%A4%A7%E2%80%94%E2%80%94%E6%AD%A3%E5%90%91%E4%BC%A0%E6%92%AD%E4%B8%8E%E6%8D%9F%E5%A4%B1">3.2 第一步：算一算当前差距多大——正向传播与损失</h4> <br><p>回归线 + 残差图:</p> <br><p class="img-center"><img alt="" height="267" src="https://i-blog.csdnimg.cn/direct/7d0902cf8ce644e0a33684064f7ea5f0.png" width="400" /></p> <br><p>预测值与真实值之间的距离就是误差，损失函数负责量化差距。</p> <br><p></p> <br><p>从输入 x 出发，沿公式一路算到最终评价，这个过程叫正向传播（forward）：</p> <br><ol><li>模型公式算出预测值：<code>z = wx + b</code></li><li>用<strong>损失函数</strong>量化预测与真实的差距，这里取均方误差 MSE：<code>loss = (z − y)²</code></li></ol> <br><p>注意这一步用到的乘法、加法、减法、平方……全是《01》运算函数一章学过的东西——前面学的内容，就是在这里搭模型的。</p> <br><p><strong>数值示例</strong>：设 x = 2，w = 3，b = 1，真实值 y = 9：</p> <br><pre><code class="language-python">① 乘法:  w·x = 3 × 2 = 6<br>② 加法:  6 + b = 6 + 1 = 7                          → 预测值 z = 7<br>③ 均方误差: loss = (z − y)² = (7 − 9)² = 4          → 损失 loss = 4<br></code></pre> <br><p>损失是一个数：越大效果越差，0 代表预测完美。可是损失算出来之后呢？怎么把这个 4 降下去——旋钮 w、b 到底该往哪个方向拧？</p> <br><h4 id="3.3%20%E7%AC%AC%E4%BA%8C%E6%AD%A5%EF%BC%9A%E6%89%BE%E6%96%B9%E5%90%91%E2%80%94%E2%80%94%E4%BB%80%E4%B9%88%E6%98%AF%E6%A2%AF%E5%BA%A6" name="3.3%20%E7%AC%AC%E4%BA%8C%E6%AD%A5%EF%BC%9A%E6%89%BE%E6%96%B9%E5%90%91%E2%80%94%E2%80%94%E4%BB%80%E4%B9%88%E6%98%AF%E6%A2%AF%E5%BA%A6">3.3 第二步：找方向——什么是梯度</h4> <br><p>单个参数时, 损失是参数的函数，比如 loss = (wx+b - y)²。导数 ∂loss/∂w 回答的就是："w 这个旋钮拧大一丁点，loss 会变多少？" 导数是单参数情形下的"变化率"。</p> <br><p><strong>多个参数时，每个参数各求一个导数，组成一组——这一组就叫梯度。</strong> 比如 loss 由 w 和 b 两个参数决定，梯度就是 (∂loss/∂w, ∂loss/∂b) 这一组数。一个参数配一个导数，几个参数就有几个分量。所以梯度不是什么新东西，就是"把所有参数的导数打包在一起"。</p> <br><p>梯度方向 / 曲面图:</p> <br><p class="img-center"><img alt="" height="253" src="https://i-blog.csdnimg.cn/direct/d92bc8f631b041c0954370d7dfc3e9a0.png" width="377" /></p> <br><p>梯度是多个参数导数组成的向量；它指出损失变化最快的方向。</p> <br><p></p> <br><p><strong>梯度指示调参方向。</strong> 关键在导数的正负：</p> <br><ul><li> <p>导数为负 → 参数增大一点，损失反而下降 → 这个参数该加</p> </li><li> <p>导数为正 → 参数增大一点，损失上升 → 这个参数该减</p> </li></ul> <br><p>导数怎么算？具体计算交给机器, 这里一笔带过地演示一次，好知道机器在算什么。沿用上面的数：loss = (z−y)²，z = wx + b：</p> <br><pre><code class="language-python">∂loss/∂w = 2(z−y)·x = 2×(7−9)×2 = -8     (内层: ∂z/∂w = x)<br>∂loss/∂b = 2(z−y)·1 = 2×(7−9)×1 = -4     (内层: ∂z/∂b = 1)<br></code></pre> <br><p>两个梯度都是负的 → w、b 都应该增大。这个结论马上用进更新公式（见 3.4）。</p> <br><h4 id="3.4%20%E7%AC%AC%E4%B8%89%E6%AD%A5%EF%BC%9A%E6%B2%BF%E6%96%B9%E5%90%91%E6%9B%B4%E6%96%B0%E2%80%94%E2%80%94%E6%A2%AF%E5%BA%A6%E4%B8%8B%E9%99%8D" name="3.4%20%E7%AC%AC%E4%B8%89%E6%AD%A5%EF%BC%9A%E6%B2%BF%E6%96%B9%E5%90%91%E6%9B%B4%E6%96%B0%E2%80%94%E2%80%94%E6%A2%AF%E5%BA%A6%E4%B8%8B%E9%99%8D">3.4 第三步：沿方向更新——梯度下降</h4> <br><p>梯度下降等高线图:</p> <br><p class="img-center"><img alt="" height="375" src="https://i-blog.csdnimg.cn/direct/59e9ad60b18d467892ab42a7ef610aa3.webp" width="350" /></p> <br><p>一个点经过若干次迭代逐步逼近极小值(参数经过多次更新逐步逼近最低点), 很好解释 <code>参数新 = 参数旧 - lr×grad</code></p> <br><p>这里给出两条更新公式：</p> <br><pre><code class="language-python">权重更新:  w新 = w旧 − 学习率 × 梯度<br>偏置更新:  b新 = b旧 − 学习率 × 梯度<br></code></pre> <br><ul><li><strong>学习率（Learning Rate）</strong>：每次更新的步子大小，太大会震荡、太小会太慢，常取 0.1、0.01 等。</li><li>公式里的<strong>减号</strong>：梯度指向损失上升最快的方向，沿它的反方向走损失才会下降</li><li>这个算法叫<strong>梯度下降法（Gradient Descent）</strong>：沿梯度反方向一小步一小步挪，损失随之下降。</li></ul> <br><p><strong>数值示例：手动更新一次</strong>。w = 3，梯度 −8；b = 1，梯度 −4；学习率取 0.1：</p> <br><pre><code class="language-python">w新 = 3 − 0.1×(−8) = 3.8<br>b新 = 1 − 0.1×(−4) = 1.4<br></code></pre> <br><p>验证效果：新预测值 z = 3.8×2 + 1.4 = <strong>9.0</strong>，正好等于真实值，损失 = 0！</p> <br><blockquote> <br> <p>别激动——这是一维问题且数字是设计好的，才一步到位。真实模型是多维、非线性的，要重复"正向 → 反向 → 更新"很多轮，损失才逐步下降（见 3.9、3.10）。</p> <br></blockquote> <br><p><strong>代码中更新参数</strong>：</p> <br><p></p> <br><blockquote> <br> <p><strong>补语法：<code>with torch.no_grad():</code></strong></p> <br> <p>这是 Python 的 <code>with</code> 语句（上下文管理器），套路固定：</p> <br> <pre><code class="language-python">with 模式开关:<br>    缩进块里的代码   # ← 只在这个块内, 临时处于该模式<br># 缩进结束, 自动退出模式, 不用手动关闭<br></code></pre> <br> <p>模式的生效范围就是缩进块，进入和退出全自动。</p> <br></blockquote> <br><p><code>torch.no_grad()</code> 就是 PyTorch 提供的一个"模式开关"：在这个块里做的所有运算，都不记录进计算图、不追踪梯度。</p> <br><p><strong>为什么更新参数时必须关追踪</strong>：更新公式 <code>w -= lr * w.grad</code> 本身也是一次运算。更新只是尝试和调整的动作，不是要学习的内容——若它也被记进计算图，图上就会混入一堆调参动作，下一轮 backward 沿图反向走时会算出错的梯度。所以规矩是：正向传播、算 loss 时不关（要建图）；更新参数时关（不建图）。</p> <br><pre><code class="language-python">lr = 0.1<br>with torch.no_grad():<br>w -= lr * w.grad     # w新 = w旧 − 学习率 × 梯度<br>b -= lr * b.grad<br>w.grad.zero_()           # 梯度清零, 为下一轮做准备 (为什么必须清零: 见 3.6 注意③)<br>b.grad.zero_()<br>print(w)   # tensor(3.8000, requires_grad=True)<br>print(b)   # tensor(1.4000, requires_grad=True)</code></pre> <br><ul><li>更新要放在 <code>torch.no_grad()</code> 里。</li><li>用 <code>-=</code> 就地修改，w 仍是原来那个叶子张量；若写成 <code>w = w - lr * w.grad</code>，会创建新张量、丢掉追踪身份。</li></ul> <br><p><strong>用 .data 更新</strong></p> <br><pre><code class="language-python"># 代入权重更新公式: w新 = w旧 − 学习率 × 梯度<br>w.data = w.data - 0.01 * w.grad<br></code></pre> <br><p><code>.data</code> 是张量里"绕过追踪的原始数据"，直接改它 autograd 不会阻拦（.data 的风险见 3.8）——这是用的历史写法；新代码推荐 <code>with torch.no_grad():</code>，语义更清晰也更安全。</p> <br><p>两种写法都必须注意：不能写 <code>w = w - ...</code>，那会创建新张量、丢掉 requires_grad 身份。</p> <br><p></p> <br><p>带箭头的梯度下降路径:</p> <br><p class="img-center"><img alt="" height="293" src="https://i-blog.csdnimg.cn/direct/1a9334ea3d7e432da9286ff3f2803081.webp" width="400" /></p> <br><p>箭头越来越短，直观表现“越靠近最优值，更新步子越小”</p> <br><p></p> <br><h4 id="3.5%20%E7%9C%9F%E6%AD%A3%E7%9A%84%E9%9A%BE%E9%A2%98%EF%BC%9A%E7%99%BE%E4%B8%87%E4%B8%AA%E5%8F%82%E6%95%B0%EF%BC%8C%E6%A2%AF%E5%BA%A6%E6%80%8E%E4%B9%88%E7%AE%97%E5%BE%97%E8%BF%87%E6%9D%A5" name="3.5%20%E7%9C%9F%E6%AD%A3%E7%9A%84%E9%9A%BE%E9%A2%98%EF%BC%9A%E7%99%BE%E4%B8%87%E4%B8%AA%E5%8F%82%E6%95%B0%EF%BC%8C%E6%A2%AF%E5%BA%A6%E6%80%8E%E4%B9%88%E7%AE%97%E5%BE%97%E8%BF%87%E6%9D%A5">3.5 真正的难题：百万个参数，梯度怎么算得过来</h4> <br><p>回到 3.3 被我们"一笔带过"的求导。给一两个参数手推链式法则不难，但——</p> <br><ul><li>真实神经网络动辄百万、上亿个参数，每个都要对损失求导，手算根本不可能；</li><li>而且算式怎么搭，求导路径就跟着怎么变，导数无法事先写死。</li></ul> <br><p>PyTorch 的答案是 <code>torch.autograd</code>（自动微分模块）：你只管像 3.2 那样把算式搭出来，它自动算出所有参数的梯度，支持任意结构的计算图。</p> <br><p><strong>它凭什么能自动算？靠两样东西：</strong></p> <br><p><strong>① 计算图（Computation Graph）：正向搭算式时自动记录的"运算路线图"</strong></p> <br><p class="img-center"><img alt="" height="81" src="https://i-blog.csdnimg.cn/direct/a36226e4fb144de78c39360367724156.png" width="300" /></p> <br><p>每做一步运算，PyTorch 就悄悄记下一个节点。下面给出流程图（仍以 y = wx + b + MSE 为例）：</p> <br><p class="img-center"><img alt="" height="53" src="https://i-blog.csdnimg.cn/direct/1afaec146ab847e28604575ba12be0d1.png" width="600" /></p> <br><pre><code class="language-python">正向传播（左→右，算出损失）：<br>  x ──► ①×(w·x) ──► ②+(+b) ──► z ──► ③MSE ──► loss<br>        ▲              ▲                     ▲<br>        w              b                     y(真实值)<br>        └────── 要学习的参数 Parameters ──────┘<br>反向传播（右→左）：从 loss 出发逐层求导，把梯度回传给 w、b</code></pre> <br><p class="img-center"><img alt="" height="57" src="https://i-blog.csdnimg.cn/direct/f08579865c0d484aae85cb1aa079c892.png" width="600" /></p> <br><p>图中每个节点的身份：</p> <br><table><thead><tr><th>节点</th><th>类型</th><th>说明</th></tr></thead><tbody><tr><td>x、y</td><td>输入数据</td><td>特征 / 真实标签，不需要求梯度</td></tr><tr><td>w、b</td><td><strong>参数</strong></td><td>可训练，靠梯度更新</td></tr><tr><td>×、+</td><td>运算节点</td><td>分别计算 w·x、w·x+b</td></tr><tr><td>z</td><td>中间结果</td><td>预测值</td></tr><tr><td>MSE</td><td>损失函数</td><td>衡量 z 与 y 的差异</td></tr><tr><td>loss</td><td>最终输出</td><td>反向传播的起点</td></tr></tbody></table> <br><p>一次完整训练对应的三段：</p> <br><table><thead><tr><th>阶段</th><th>做什么</th><th>图上方向</th></tr></thead><tbody><tr><td><strong>正向传播</strong></td><td>数据 → 预测值 → 和真实值比 → 得到损失</td><td>左 → 右</td></tr><tr><td><strong>反向传播</strong></td><td>从损失往回逐层求导，得到每个参数的梯度</td><td>右 → 左</td></tr><tr><td><strong>参数更新</strong></td><td>用梯度按 3.4 的公式调整 w、b</td><td>图外公式</td></tr></tbody></table> <br><p><strong>② 反向传播（Backpropagation）：沿计算图往回逐层套链式法则</strong></p> <br><p>Backpropagation 神经网络图:</p> <br><p class="img-center"><img alt="" height="487" src="https://i-blog.csdnimg.cn/direct/bc211b7b50404c59a3fc8e3adb60b833.png" width="450" /></p> <br><p>误差从输出端向前层传播，逐层计算梯度。</p> <br><p></p> <br><p>图是正向记的，求导却要反过来走：从最右端的 loss 出发，每经过一个节点就套一次链式法则，一路把梯度回传给 w、b。这个"沿计算图反向执行链式法则"的过程，就叫反向传播——它不是凭空冒出来的新概念，而是 autograd"执行求导"的具体方式。《00-深度学习简介》里讲的反向传播，到这里终于有了工程实现。</p> <br><p><strong>四个容易缠在一起的词，一次理清：</strong></p> <br><table><thead><tr><th>术语</th><th>身份</th><th>一句话</th></tr></thead><tbody><tr><td>链式法则</td><td>数学方法</td><td>求复合函数导数的规则（外层导数 × 内层导数）</td></tr><tr><td>计算图</td><td>数据结构</td><td>PyTorch 正向运算时自动记录的运算路线</td></tr><tr><td>反向传播</td><td>执行过程</td><td>沿计算图反向套链式法则，把梯度算出来</td></tr><tr><td>自动微分 autograd</td><td>PyTorch 模块</td><td>提供"记录计算图 + 反向传播"的整套能力</td></tr></tbody></table> <br><blockquote> <br> <p>这正是《01》里"动态计算图"特点的落地：边搭算式边记录图，再反向求导，一条龙。</p> <br></blockquote> <br><p></p> <br><h4 id="3.6%20autograd%20%E4%B8%89%E4%BB%B6%E5%A5%97%EF%BC%9Arequires_grad%E3%80%81backward%E3%80%81grad" name="3.6%20autograd%20%E4%B8%89%E4%BB%B6%E5%A5%97%EF%BC%9Arequires_grad%E3%80%81backward%E3%80%81grad">3.6 autograd 三件套：requires_grad、backward、grad</h4> <br><p>完整代码（延续 x = 2，w = 3，b = 1，y = 9）：</p> <br><pre><code class="language-python">import torch<br>1. 数据: 不会被训练更新, 用默认的 requires_grad=False<br>x = torch.tensor(2.0)<br>y_true = torch.tensor(9.0)<br>2. 参数: 必须声明 requires_grad=True, PyTorch 才会记录它参与的运算<br>w = torch.tensor(3.0, requires_grad=True)<br>b = torch.tensor(1.0, requires_grad=True)<br>3. 正向传播: 计算图随运算自动搭建<br>z = w * x + b<br>loss = (z - y_true) ** 2<br>4. 反向传播: 一行代码, 自动算出所有参数的梯度<br>loss.backward()<br>5. 访问梯度: 结果存在每个参数的 .grad 属性里<br>print(w.grad)   # tensor(-8.)<br>print(b.grad)   # tensor(-4.)</code></pre> <br><p><code>-8.</code> 和 <code>-4.</code> 与 3.3 的手推完全一致——backward() 一次调用，链式法则全自动。</p> <br><p>三件套各自的角色：</p> <br><table><thead><tr><th>名称</th><th>类型</th><th>作用</th></tr></thead><tbody><tr><td><code>requires_grad=True</code></td><td>创建张量时的开关</td><td>声明"这个张量是参数，请追踪它参与的所有运算"</td></tr><tr><td><code>backward()</code></td><td>损失张量的方法</td><td>从 loss 出发反向遍历计算图，链式法则算出所有被追踪张量的梯度</td></tr><tr><td><code>.grad</code></td><td>张量的属性</td><td>存放 backward() 算出的梯度；只有 requires_grad=True 的张量才有</td></tr></tbody></table> <br><p>三个注意事项：</p> <br><p><strong>① 被追踪的张量必须是浮点型</strong>。整数张量开启 requires_grad 会直接报错：</p> <br><pre><code class="language-python">w = torch.tensor(3, requires_grad=True)   # 报错! int 不行<br># RuntimeError: Only Tensors of floating point... can require gradient<br></code></pre> <br><p>原因：导数是连续量的概念，整数是离散的、不可导。所以参数一律用 float。</p> <br><p><strong>② 为什么只追踪参数、不追踪数据</strong>：训练更新的是 w、b，x 和 y_true 永远不变.</p> <br><p><strong>③ 梯度会累加，用完必须清零</strong>。每调用一次 backward()，梯度会在旧值上累加而不是覆盖——3.4 代码里每轮 zero_() 的原因就在这里：</p> <br><pre><code class="language-python">loss.backward()<br>print(w.grad)        # tensor(-8.)<br>loss.backward()<br>print(w.grad)        # tensor(-16.)  ← 累加了两次!<br>w.grad.zero_()       # 手动清零, 下一轮从 0 开始<br></code></pre> <br><blockquote> <br> <p>设计成累加是为了支持"一个损失分多次 backward"的特殊场景；日常训练循环里每轮算完必须清零（见 3.9、3.10）。</p> <br></blockquote> <br><p>计算图的实体, 每个中间结果都带着 <code>grad_fn</code>：</p> <br><pre><code class="language-python">z = w * x + b<br>print(z)          # tensor(7., grad_fn=<AddBackward0>)<br>print(z.grad_fn)  # <AddBackward0> —— 记录"z 是由一次加法算出来的"<br></code></pre> <br><p><code>grad_fn</code> 是计算图的运算记录，标明"怎么算出来的"，backward() 就是顺着这条链反向走的。</p> <br><h4 id="3.7%20%E7%A1%AC%E6%80%A7%E8%A7%84%E5%AE%9A%EF%BC%9Abackward%20%E5%8F%AA%E8%83%BD%E7%94%B1%22%E6%A0%87%E9%87%8F%22%E8%B0%83%E7%94%A8" name="3.7%20%E7%A1%AC%E6%80%A7%E8%A7%84%E5%AE%9A%EF%BC%9Abackward%20%E5%8F%AA%E8%83%BD%E7%94%B1%22%E6%A0%87%E9%87%8F%22%E8%B0%83%E7%94%A8">3.7 硬性规定：backward 只能由"标量"调用</h4> <br><p>规范表述：PyTorch 不支持"向量对向量"直接求导，<code>backward()</code> 只能被标量张量（一个数）调用。如果损失是向量，先用 <code>sum()</code> / <code>mean()</code> 聚合成标量。</p> <br><p><strong>示例 1：标量张量求导</strong>（y 本身就是一个数）</p> <br><pre><code class="language-python">import torch<br>x = torch.tensor(10., requires_grad=True)   # 一个点<br>y = 2 * x ** 2                              # 一条曲线 y = 2x²<br>print(y)              # tensor(200., grad_fn=<MulBackward0>)<br>print(y.grad_fn)      # <MulBackward0>  —— y 是由"乘法"算出来的<br>y.backward()          # y 已是标量, 直接 backward<br>print(x.grad)         # tensor(40.)<br>手算: y' = 4x, x=10 -> 40  ✓</code></pre> <br><p><strong>示例 2：向量张量求导</strong>（y 是向量，必须先聚合）</p> <br><pre><code class="language-python">x = torch.tensor([10., 20.], requires_grad=True)<br>y = 2 * x ** 2<br>print(y)              # tensor([200., 800.], grad_fn=<MulBackward0>)<br>y.sum().backward()    # y 是向量, 不能直接 backward -> 先 sum 成标量<br>print(x.grad)         # tensor([40., 80.])<br>手算: sum = 2x₁² + 2x₂², 对 x₁ 求导 = 4x₁ = 40, 对 x₂ 求导 = 4x₂ = 80  ✓</code></pre> <br><p>为什么 sum 之后每个分量还能得到自己的梯度：sum 对 x₁ 的偏导只经过 y₁ 那一项（y₂ 与 x₁ 无关），所以梯度各回各的, 互不干扰。</p> <br><blockquote> <br> <p>统一写 <code>y.sum().backward()</code> 是好习惯：标量时 sum 是空操作（原样不变），向量时自动兜底。</p> <br></blockquote> <br><h4 id="3.8%20%E5%B8%A6%E6%A2%AF%E5%BA%A6%E7%9A%84%E5%BC%A0%E9%87%8F%E4%B8%8E%20NumPy%EF%BC%9Adetach()" name="3.8%20%E5%B8%A6%E6%A2%AF%E5%BA%A6%E7%9A%84%E5%BC%A0%E9%87%8F%E4%B8%8E%20NumPy%EF%BC%9Adetach()">3.8 带梯度的张量与 NumPy：detach()</h4> <br><p><strong>知识点</strong>：设置了 <code>requires_grad=True</code> 的张量不能直接转 numpy，会报错，因为 numpy 没有"追踪/求导"这套机制。</p> <br><p><strong>解决：</strong>先用 <code>detach()</code> 分离出一个不带追踪的新张量再转。</p> <br><pre><code class="language-python">import torch<br>t1 = torch.tensor([10., 20.], requires_grad=True)<br>t1.numpy()   # 报错!<br>RuntimeError: Can't call numpy() on Tensor that requires grad.<br>Use tensor.detach().numpy() instead.<br>1. detach(): 产生一个新张量, 数据共享, 但不再追踪<br>t2 = t1.detach()<br>print(t1.requires_grad)   # True<br>print(t2.requires_grad)   # False<br>2. 共享同一份内存 (改一个, 另一个跟着变)<br>print(t1.data)            # tensor([10., 20.])<br>print(t2.data)            # tensor([10., 20.])<br>print(id(t1.data) == id(t2.data))   # True —— 同一块内存<br>3. detach 后就能转 numpy 了<br>print(t2.numpy())         # [10. 20.]<br>4. 最终常用写法: 一行链式<br>n2 = t1.detach().numpy()</code></pre> <br><p>三个常见疑问：</p> <br><ul><li><strong><code>import numpy as np</code> 为什么没用到？</strong> 是的。<code>.numpy()</code> 是张量自己的方法，不需要显式 import numpy；只有直接使用 np 的功能（如 <code>np.array</code>）才需要。</li><li><strong>验证是否共享时,为什么 <code>t1[0] = 100</code> 不允许、<code>t1.data[0] = 100</code> 却允许</strong>：t1 是带追踪的叶子张量，autograd 禁止直接就地修改它（否则计算图对不上账）；<code>.data</code> 拿到的是"绕过追踪的原始数据"，改它 autograd 不管，但也有风险，训练循环外尽量别这么改参数。</li><li><strong>detach() 是拷贝吗</strong>：不是。它共享同一份内存，只是"摘掉"了追踪标记；想要独立副本要再加 <code>.copy()</code>。</li></ul> <br><h4 id="3.9%20%E5%BA%94%E7%94%A8%EF%BC%9A%E6%A2%AF%E5%BA%A6%E4%B8%8B%E9%99%8D%E6%B1%82%20y%20%3D%20x%C2%B2%20%2B%2020%20%E7%9A%84%E6%9E%81%E5%B0%8F%E5%80%BC" name="3.9%20%E5%BA%94%E7%94%A8%EF%BC%9A%E6%A2%AF%E5%BA%A6%E4%B8%8B%E9%99%8D%E6%B1%82%20y%20%3D%20x%C2%B2%20%2B%2020%20%E7%9A%84%E6%9E%81%E5%B0%8F%E5%80%BC">3.9 应用：梯度下降求 y = x² + 20 的极小值</h4> <br><p>需求：求 <code>y = x² + 20</code> 的极小值点。数学上求导 <code>y' = 2x = 0</code> 得 x = 0</p> <br><p>但梯度下降不用公式，靠迭代自己走过去，这正是"学习"的雏形：</p> <br><p>抛物线上的梯度下降(从 x=10 开始，一步步向 x=0 靠近):</p> <br><p style="text-align:center"><img alt="" src="https://i-blog.csdnimg.cn/direct/062a541ac79d48cab1aaf7d366df5aec.gif" /></p> <br><pre><code class="language-python">import torch<br>1. 定义起点<br>x = torch.tensor(10., requires_grad=True)<br>lr = 0.01<br>2. 循环迭代 1000 次<br>for i in range(1, 1001):<br>y = x ** 2 + 20                 # 3-1 正向计算<br>if x.grad is not None:          # 3-2 梯度清零(第一次还没有梯度, 要判空)<br>x.grad.zero_()<br>y.backward()                    # 3-3 反向传播: 梯度 = 2x<br>x.data = x.data - lr * x.grad   # 3-4 梯度更新(.data 写法)<br>if i % 200 == 0:<br>    print(f'第{i}次: x={x.item():.6f}, y={y.item():.6f}')<br>print(f'最终: x={x.item():.6f}, y={y.item():.6f}')</code></pre> <br><p>输出（示例，按每轮 x ← 0.98x 逐轮推得）：</p> <br><pre><code class="language-python">第200次: x=0.175866, y=20.030930<br>第400次: x=0.003093, y=20.000010<br>第600次: x=0.000054, y=20.000000<br>第800次: x=0.000001, y=20.000000<br>最终: x=0.000000, y=20.000000<br></code></pre> <br><p><strong>为什么每轮 x 变成上一轮的 0.98 倍</strong>：梯度 = 2x，更新 <code>x ← x − 0.01×2x = 0.98x</code>。离 0 越远步子越大、越近步子越小，自然"刹车"——最终收敛到极小值点 x = 0，y = 20。</p> <br><p>不同学习率的下降步长:</p> <br><p class="img-center"><img alt="" height="240" src="https://i-blog.csdnimg.cn/direct/ac80bbdec4e34f05a7ab867de4cb9ec4.png" width="600" /></p> <br><p>学习率小 → 慢；太大 → 容易跨过最优点或震荡。</p> <br><p>每一轮输出的 x（新）成为下一轮输入的 x（旧），循环往复直到收敛。\</p> <br><p></p> <br><h4 id="3.10%20%E5%AE%8C%E6%95%B4%E7%A4%BA%E4%BE%8B%EF%BC%9A%E8%BF%B7%E4%BD%A0%E8%AE%AD%E7%BB%83%E5%BE%AA%E7%8E%AF" name="3.10%20%E5%AE%8C%E6%95%B4%E7%A4%BA%E4%BE%8B%EF%BC%9A%E8%BF%B7%E4%BD%A0%E8%AE%AD%E7%BB%83%E5%BE%AA%E7%8E%AF">3.10 完整示例：迷你训练循环</h4> <br><p>把"正向 → 反向 → 更新 → 清零"串成循环，让机器自己把 w、b 学出来。数据背后的真实规律是 <code>y = 2x + 1</code>，但代码不知道, 看它能不能学回来：</p> <br><pre><code class="language-python">import torch<br>数据: 3 个样本, 背后规律是 y = 2x + 1 (代码不知道)<br>x = torch.tensor([1.0, 2.0, 3.0])<br>y = torch.tensor([3.0, 5.0, 7.0])<br>参数从 0 开始学<br>w = torch.tensor(0.0, requires_grad=True)<br>b = torch.tensor(0.0, requires_grad=True)<br>lr = 0.1   # 学习率<br>for epoch in range(1, 5):<br>pred = w * x + b                   # 1. 正向传播: 预测值(一批一起算)<br>loss = ((pred - y) ** 2).mean()    # 2. 均方误差 MSE: 差的平方取平均<br>loss.backward()                    # 3. 反向传播: 自动算出 w.grad、b.grad<br><br>with torch.no_grad():              # 4. 参数更新<br>    w -= lr * w.grad<br>    b -= lr * b.grad<br><br>w.grad.zero_()                     # 5. 梯度清零<br>b.grad.zero_()<br><br>print(f'第{epoch}轮  loss={loss.item():.4f}  w={w.item():.4f}  b={b.item():.4f}')</code></pre> <br><p>输出：</p> <br><pre><code class="language-python">第1轮  loss=27.6667  w=2.2667  b=1.0000<br>第2轮  loss=0.3319   w=2.0178  b=0.8933<br>第3轮  loss=0.0053   w=2.0439  b=0.9076<br>第4轮  loss=0.0013   w=2.0399  b=0.9085<br></code></pre> <br><p><strong>第一轮手算核对</strong>：</p> <br><pre><code class="language-python">pred = [0, 0, 0]  差 = pred - y = [-3, -5, -7]<br>loss = (9 + 25 + 49) / 3 = 83/3 ≈ 27.6667<br>w.grad = 2×(−3×1 + −5×2 + −7×3)/3 = −68/3 ≈ −22.6667<br>b.grad = 2×(−3 −5 −7)/3 = −10<br>更新: w = 0 − 0.1×(−22.6667) = 2.2667;  b = 0 − 0.1×(−10) = 1.0<br></code></pre> <br><p>看趋势：loss 从 27.7 → 0.33 → 0.005 → 0.001，一路下降；w、b 一路逼近真实规律 <strong>2 和 1</strong>。这就是"学习"的本质：反复用梯度把参数往损失更低的方向挪。</p> <br><blockquote> <br> <p>实际开发中，第 4、5 步通常交给优化器（<code>torch.optim</code>，如 SGD、Adam）和 <code>optimizer.zero_grad()</code> 代劳——第四节的线性回归案例就是这么做的。这里手写一遍，是为了看清它替你做了什么。</p> <br></blockquote> <br><h4 id="3.11%20%E5%BA%94%E7%94%A8%EF%BC%9A%E5%A4%9A%E7%BB%B4%E6%95%B0%E6%8D%AE%E7%9A%84%E4%B8%80%E6%AC%A1%E6%A2%AF%E5%BA%A6%E8%AE%A1%E7%AE%97" name="3.11%20%E5%BA%94%E7%94%A8%EF%BC%9A%E5%A4%9A%E7%BB%B4%E6%95%B0%E6%8D%AE%E7%9A%84%E4%B8%80%E6%AC%A1%E6%A2%AF%E5%BA%A6%E8%AE%A1%E7%AE%97">3.11 应用：多维数据的一次梯度计算</h4> <br><p>真实模型的输入不是一个数，而是一批数据（矩阵）。这是自动微分最真实的应用场景</p> <br><p>一次走通"前向 → 损失 → 反向"：</p> <br><pre><code class="language-python">import torch<br>1. 输入 x: 2 个样本, 每个样本 5 个特征 -> (2, 5) 全 1<br>x = torch.ones(2, 5)<br>2. 真实值 y: 2 个样本, 每个样本 3 个输出 -> (2, 3) 全 0<br>y = torch.zeros(2, 3)<br>3. 参数: 权重 (5, 3), 偏置 (3,) —— 形状不是随便定的!<br>w = torch.randn(5, 3, requires_grad=True)<br>b = torch.randn(3, requires_grad=True)<br>4. 前向传播: 矩阵乘法 + 加偏置<br>z = torch.matmul(x, w) + b       # (2,5)·(5,3) -> (2,3), b 广播到每行<br>5. 损失函数: 均方误差 (nn = neural network 神经网络模块)<br>criterion = torch.nn.MSELoss()<br>loss = criterion(z, y)<br>6. 反向传播: 一次算出全部参数的梯度<br>loss.backward()<br>print(w.grad.shape)   # torch.Size([5, 3])  与 w 同形状<br>print(b.grad.shape)   # torch.Size([3])     与 b 同形状</code></pre> <br><p>（输出只记形状：w、b 是随机初始化的，每次运行数值不同，但形状恒定。）</p> <br><p>集中回答几个的点：</p> <br><ul><li><strong>为什么 w 是 (5, 3)</strong>：矩阵乘法规则——<code>(2,5)·(5,3)</code> 中 x 的列数 5 必须等于 w 的行数 5，结果取外侧 <code>(2,3)</code>。5 = 输入特征数，3 = 输出维度（可理解为 3 个神经元）。w 的每一行管一个特征、每一列管一个输出。</li><li><strong>偏置 b</strong>：每个输出神经元配一个可学习的常数，形状 <code>(3,)</code> 就是 3 个输出各一个；<code>(2,3) + (3,)</code> 按广播规则加到每一行。</li><li>这里的 <code>z = x@w + b</code> 就是 3.5 计算图的多维版：乘法→加法→MSE，链条一模一样，只是节点从数字变成了矩阵。</li></ul> <br><h4 id="3.12%20%E5%81%8F%E7%BD%AE" name="3.12%20%E5%81%8F%E7%BD%AE">3.12 偏置</h4> <br><p>实际开发中，大多数情况下可以不考虑偏置，会将偏置矩阵直接设置为全 0 矩阵。（流程图上仍画出 b，是为了保证理论完整；工程上常做这个简化。）</p> <br><p>为什么可以这样：</p> <br><ul><li>偏置的作用只是给预测值"平移"一个常数，影响小；</li><li>全 0 的偏置在训练中照样能被梯度更新挪到合适的位置，不吃亏；</li><li>PyTorch 的 <code>nn.Linear</code> 提供了开关：<code>nn.Linear(in_features, out_features, bias=False)</code>，需要省略时一行搞定。</li></ul> <br><h3 name="%E5%9B%9B%E3%80%81%E6%A1%88%E4%BE%8B%EF%BC%9A%E7%BA%BF%E6%80%A7%E5%9B%9E%E5%BD%92" style="background-color:transparent"></h3> <br><h3 id="%E5%9B%9B%E3%80%81%E6%A1%88%E4%BE%8B%EF%BC%9A%E7%BA%BF%E6%80%A7%E5%9B%9E%E5%BD%92" name="%E5%9B%9B%E3%80%81%E6%A1%88%E4%BE%8B%EF%BC%9A%E7%BA%BF%E6%80%A7%E5%9B%9E%E5%BD%92" style="background-color:transparent">四、案例：线性回归</h3> <br><h4 id="4.1%20%E6%A1%88%E4%BE%8B%E7%9B%AE%E6%A0%87%E4%B8%8E%E5%9B%9B%E6%AD%A5%E6%B5%81%E7%A8%8B" name="4.1%20%E6%A1%88%E4%BE%8B%E7%9B%AE%E6%A0%87%E4%B8%8E%E5%9B%9B%E6%AD%A5%E6%B5%81%E7%A8%8B">4.1 案例目标与四步流程</h4> <br><p>目标：给一堆带噪声的散点 (x, y)，让模型自己找出那条最贴近的直线 <code>y = wx + b</code>。</p> <br><p>带噪声的散点图:</p> <br><p class="img-center"><img alt="" height="263" src="https://i-blog.csdnimg.cn/direct/d754c0301d114ab290bf145e3651d6fa.png" width="400" /></p> <br><p><code>noise</code> 让点不完全落在直线上，更接近真实数据</p> <br><p></p> <br><table><thead><tr><th>步骤</th><th>说明</th><th>用到的工具</th></tr></thead><tbody><tr><td><strong>1. 准备训练集数据</strong></td><td>造数据、打包、分批</td><td><code>make_regression</code> → <code>TensorDataset</code> → <code>DataLoader</code></td></tr><tr><td><strong>2. 构建模型</strong></td><td>定义假设函数 y = wx + b</td><td><code>nn.Linear</code></td></tr><tr><td><strong>3. 设置损失函数和优化器</strong></td><td>衡量误差 + 自动更新参数</td><td><code>nn.MSELoss()</code> + <code>optim.SGD()</code></td></tr><tr><td><strong>4. 模型训练</strong></td><td>前向 → 反向 → 更新，循环多轮</td><td>训练循环</td></tr></tbody></table> <br><p><strong>优化器是什么</strong>：3.10 里我们手写 <code>w.data -= lr * grad</code>——参数一多就写不过来了。优化器（optimizer）就是"替你执行更新公式"的工具：你把参数交给它，它记住每个参数的梯度，<code>step()</code> 一调用，所有参数按公式自动更新。常用的 SGD、Adam 只是"更新公式"不同。</p> <br><p></p> <br><h4 id="4.2%20%E5%87%86%E5%A4%87%E6%95%B0%E6%8D%AE%EF%BC%9Amake_regression" name="4.2%20%E5%87%86%E5%A4%87%E6%95%B0%E6%8D%AE%EF%BC%9Amake_regression">4.2 准备数据：make_regression</h4> <br><pre><code class="language-python">from sklearn.datasets import make_regression<br>import matplotlib.pyplot as plt<br>plt.rcParams['font.sans-serif'] = ['SimHei']   # Windows: 正常显示中文<br>plt.rcParams['axes.unicode_minus'] = False     # 正常显示负号<br>def create_dataset():<br>x, y, coef = make_regression(<br>n_samples=100,     # 100 条样本 (100 个点)<br>n_features=1,      # 每条样本 1 个特征 (一元回归)<br>noise=1.0,         # 噪声强度: 值越大散点越分散<br>coef=True,         # 返回真实系数 (默认 False 返回 None)<br>bias=14.5,         # 真实偏置<br>random_state=3,    # 随机种子: 相同则生成的数据相同<br>)<br>print(type(x))                       # <class 'numpy.ndarray'>  —— 出来是 numpy 数组<br>x = torch.tensor(x, dtype=torch.float32)   # 转成张量<br>y = torch.tensor(y, dtype=torch.float32)<br>return x, y, coef</code></pre> <br><p><strong>集中回答</strong>：</p> <br><ul><li><strong>为什么有噪声更好</strong>：真实世界的数据从来不是完美直线，总带测量误差、随机扰动。噪声让点<strong>离散地分布在直线两侧</strong>——模型必须"从乱中找规律"，这样的训练才接近实战。全是完美直线上的点，训练毫无难度，也检验不出模型能力。</li><li><strong>噪声的量级</strong>：<code>noise</code> 是噪声的标准差。 如果写<code>noise=True是</code>不规范写法（<code>True</code> 被当成数字 <code>1</code>），效果等于 <code>noise=1.0</code>，建议直接写数字。</li><li><strong>bias可以随便设置吗</strong>：可以。它只是我们<strong>人为假定的"真实规律"</strong>的一部分，定多少都行——它的用途是最后和模型学到的 bias 对比，看训练准不准。</li><li><strong>random_state</strong>：随机种子（《01》随机张量一节的老朋友），保证每个人生成的数据集一样。</li><li><strong>中文显示的字体问题</strong>：Windows 用 <code>SimHei</code>（黑体）；Mac 上换成 <code>'Arial Unicode MS'</code> 或 <code>'PingFang SC'</code>。</li></ul> <br><h4 id="4.3%20TensorDataset%20%E4%B8%8E%20DataLoader" name="4.3%20TensorDataset%20%E4%B8%8E%20DataLoader">4.3 TensorDataset 与 DataLoader</h4> <br><p>数据链路：<strong>numpy → 张量 → 数据集对象 → 数据加载器</strong>。</p> <br><pre><code class="language-python">from torch.utils.data import TensorDataset   # 构造数据集对象<br>from torch.utils.data import DataLoader      # 数据加载器<br>dataset = TensorDataset(x, y)      # 把 (特征, 标签) 打包成一条条样本对<br>dataloader = DataLoader(<br>dataset,          # 参1: 数据集对象<br>batch_size=16,    # 参2: 每批 16 条<br>shuffle=True,     # 参3: 每轮开始前打乱顺序<br>)</code></pre> <br><p><strong>集中回答</strong>：</p> <br><ul><li><strong>TensorDataset 干什么</strong>：把 x 和 y 按"第 i 个 x 配第 i 个 y"包成对，取出来就是 <code>(train_x, train_y)</code> 一对。</li><li><strong>100 条、每批 16 条，为什么是 7 批</strong>：16 × 6 = 96，装完 6 批还剩 4 条 → 再装第 7 批（只有 4 条）。即 批数 = ⌈100 / 16⌉ = 7，最后一批 <code>(16,16,16,16,16,16,4)</code>。代码里 <code>for train_x, train_y in dataloader</code> 每次取一批，循环 7 次。</li><li><strong>为什么训练集要打乱（shuffle=True）、测试集不打乱</strong>： <br>  <ul><li>训练打乱 → 每轮的批组合都不同，模型不会"记住数据的先后顺序"，参数更新更有代表性；</li><li>测试不打乱 → 评估只算指标、不更新参数，顺序本就无影响，不打乱保证结果可复现、可对比。</li></ul> </li></ul> <br><h4 id="4.4%20%E6%A8%A1%E5%9E%8B%EF%BC%9Ann.Linear(1%2C%201)" name="4.4%20%E6%A8%A1%E5%9E%8B%EF%BC%9Ann.Linear(1%2C%201)">4.4 模型：nn.Linear(1, 1)</h4> <br><p>带斜率和截距的回归线:</p> <br><p class="img-center"><img alt="" height="206" src="https://i-blog.csdnimg.cn/direct/790d370a07ba4451a552c53702d97238.png" width="200" /></p> <br><p>把 <code>y=wx+b</code> 中的 w、b 和直线的斜率、截距对应起来。</p> <br><p></p> <br><pre><code class="language-python">from torch import nn    # nn = neural network<br>model = nn.Linear(in_features=1, out_features=1)</code></pre> <br><ul><li><code>nn.Linear</code> 就是内置的<strong>假设函数</strong> <code>y = wx + b</code>（也叫线性层/全连接层）。</li><li><code>in_features=1</code>：输入特征数（对应 x）；<code>out_features=1</code>：输出维度（对应 y）, 注意大写 Linear，类名。</li><li>它内部自动创建参数 <code>model.weight</code>（w）和 <code>model.bias</code>（b），并且已经设好 <code>requires_grad=True</code>, 不用我们手动声明。</li><li>对照 3.11 的多维例子：<code>nn.Linear(5, 3)</code> 就等价于 w(5,3) + b(3)。</li></ul> <br><h4 id="4.5%20%E6%8D%9F%E5%A4%B1%E5%87%BD%E6%95%B0%EF%BC%9Ann.MSELoss()" name="4.5%20%E6%8D%9F%E5%A4%B1%E5%87%BD%E6%95%B0%EF%BC%9Ann.MSELoss()">4.5 损失函数：nn.MSELoss()</h4> <br><pre><code class="language-python">criterion = nn.MSELoss()                    # criterion = "标准"，损失函数的惯用变量名<br>loss = criterion(y_pred, train_y.reshape(-1, 1))<br></code></pre> <br><ul><li>均方误差：3.5 计算图里的 MSE，衡量预测与真实的平均平方差。</li><li><strong><code>reshape(-1, 1)</code> 的 -1 </strong>：-1 表示"这一维自动推算"——总元素数不变，剩下的维度定了，-1 那维自动算出来。<code>train_y</code> 原形状 (16,)，reshape(-1,1) → (16,1)，和 y_pred 的 (16,1) 对齐才能逐元素算误差。</li></ul> <br><h4 id="4.6%20%E4%BC%98%E5%8C%96%E5%99%A8%EF%BC%9Aoptim.SGD" name="4.6%20%E4%BC%98%E5%8C%96%E5%99%A8%EF%BC%9Aoptim.SGD">4.6 优化器：optim.SGD</h4> <br><pre><code class="language-python">from torch import optim<br>optimizer = optim.SGD(params=model.parameters(), lr=1e-2)   # lr=0.01</code></pre> <br><ul><li><strong>SGD</strong>（Stochastic Gradient Descent，随机梯度下降）：每次用一小批数据估梯度、更新一次——"随机"就来自批的随机性。</li><li><code>model.parameters()</code>：把模型里所有参数（weight、bias）打包交给优化器管理。</li><li>训练（替代 3.4 的手动更新）：</li></ul> <br><pre><code class="language-python">optimizer.zero_grad()   # 1. 梯度清零 —— 内部会遍历所有参数处理, 不用手动判空<br>loss.backward()         # 2. 反向传播算梯度<br>optimizer.step()        # 3. 执行更新: w新 = w旧 - lr × 梯度<br></code></pre> <br><blockquote> <br> <p>对比 3.4：<code>x.grad.zero_()</code> + <code>x.data = ...</code> 两步手动操作，现在由 <code>zero_grad()</code> + <code>step()</code> 代劳。</p> <br></blockquote> <br><h4 torch<br>from torch.utils.data import TensorDataset, DataLoader<br>from torch import nn, optim<br>from sklearn.datasets import make_regression<br>import matplotlib.pyplot as               # 假设函数 y = wx + b<br>criterion = nn.MSELoss()                      # 损失函数<br>optimizer = optim.SGD(model.parameters(), lr=0.01)   # 优化器<br><br>epochs, loss_list = 100, []<br>for epoch in
